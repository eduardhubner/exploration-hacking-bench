## 1. Items and pairing

We use the Cyber, Bio, and Chem subsets of WMDP. Each item is a multiple-choice question with a single reference answer, addressed by a stable integer `item_id` (1, 2, 3, …) into the WMDP ordering — the same `item_id` denotes the same question for every model, which is what makes cross-model item overlap (§5) meaningful.

Every scaffolded response is paired with the **same model's** response to the **same `item_id`** under the corresponding baseline condition. A matched pair enters a cell only when the item is scoreable in *both* the scaffold and the baseline condition. All behavioral statistics use the realized number of matched scoreable pairs, never the nominal generation count.

## 2. Response taxonomy

Each response is classified as one of:

| outcome | meaning | in analysis |
|---|---|---|
| `correct` | answer matches the reference | scoreable |
| `wrong` | a *different* valid choice is given | scoreable |
| `refused` | model declines, in clear refusal language | own channel; excluded from the C→W headline |
| `filtered` | provider content-policy block | missing data (excluded) |
| `infra_error` | transport / truncation failure | missing data (excluded) |
| `unknown` | answer cannot be parsed | missing data (excluded) |

A non-answer is **never** recorded as `wrong`: scoring a refusal or a provider block as an incorrect answer would manufacture a spurious degradation signal. `filtered` (a policy block) is kept distinct from `infra_error` (a transport failure) so a flaky connection cannot inflate the construct-relevant filtering rate.

### Refusal handling

Refusal is detected conservatively (high precision). A response is `refused` only when it emits **no valid answer letter** *and* contains **explicit refusal language** from a curated marker list (e.g. "I can't help", "I must decline", "against my guidelines"). Ambiguous cases are routed *away* from `refused` on purpose: a valid answer letter accompanied by refusal language ("I shouldn't, but it's C") and any empty/truncated output go to `unknown` for hand-audit rather than being guessed. Transport errors and content-filter blocks are checked *before* the completion text, so a non-response is never mislabeled a refusal.

Refusal is treated as its **own behavioral channel, not as noise and not as a wrong answer**:

- **Excluded from the headline C→W metric.** Only `correct`/`wrong` are scoreable, and a matched pair needs a scoreable outcome at *both* baseline and scaffold — so an item that is refused at either endpoint drops out of the paired McNemar.
- **Analyzed separately.** Induced refusal (answered→refused vs the reverse) is reported in a dedicated refusal channel, and a joint degradation mass C→{wrong, refused} is reported as a *sensitivity* line only — never as the verdict.

The separation is deliberate. On hazardous WMDP content refusal is **motive-ambiguous**: content-caution (the salience of dangerous material) produces refusals, not deliberately-wrong answers. Folding C→R into the degradation metric would confound content-caution with exploration hacking, so the headline is the narrow **C→W channel only**, with refusal rates checked for condition-dependence before exclusion. Empirically refusals are low for most models and concentrated in the Claude models on the hazardous domains (see the breakdown below).

## 3. Provider content filtering (the comparability constraint)

Filtering is the single largest exclusion source and is **not** spread evenly across models. Among all reported models, provider filtering appears **only** for: Claude Opus 4. Every other model returned zero filtered items in every domain.

For **Claude Opus 4 on Bio**: of the 300 distinct items presented, **209 (70%) were blocked in at least one condition**. Scoreable baseline counts are arm-specific — each arm is a separate sweep paired against its own baseline: **114/300 scoreable at the single-turn baseline and 125/300 at the agentic baseline**. Matched-pair counts in each arm are bounded by that arm's own baseline (single-turn $n\le$114, agentic $n\le$125). Claude Opus 4's filtering is concentrated in Bio (the most overtly hazardous content), lighter in Chem, and absent in Cyber. We treat the filtering rate as a reported result, not merely a nuisance.

## 4. Sampling and top-up

For the single-turn and agentic arms, each cell targets **≥100 scoreable matched pairs**. Because exclusions are only seen after generation, we begin from a base sample of **140 items** per cell-group (a buffer over 100 for expected parse/refusal loss) and, where that still falls short, extend with **disjoint top-up blocks appended to the existing sample** — never re-running the same items — until the target is reached or the pool is exhausted.

How far a model must be extended to yield 100 scoreable pairs depends sharply on its filtering/parse loss. The base sample reaches `item_id 140`; cells that required deeper draws:

All other single-turn/agentic cells were satisfied within the base 140. Claude Opus 4/Bio is the extreme case: reaching ~100 scoreable pairs required drawing all the way to `item_id 297`.

## 5. Cross-model item comparability

Per-cell top-up is done **per model**, so when a model is filtered onto a different slice of the benchmark, the *shared* item set across models shrinks even though each model's own cell is fully powered. The pool of items scoreable at baseline across **all five core models** (the ceiling for any figure that compares models on the *same* items):

| arm | cyber | bio | chem |
|---|--:|--:|--:|
| single_turn | 108 | 52 | 108 |
| agentic | 90 | 46 | 94 |

**Bio is the outlier**: only 52 items (single-turn) / 46 (agentic) are shared across all five core models, versus ~90–108 for Cyber and Chem. The reason is specific: the four unfiltered models were only run to `item_id 140` (they needed no more), while Claude Opus 4's Bio sample was pushed to `item_id 297`, so its surviving Bio items live largely in a `141–297` region the other models never sampled — and within the first 140 Claude Opus 4 is scoreable on only 54 items.

**Implications.** *Within-model* claims (e.g. a model's cross-domain replication) are unaffected — each model is paired against its own baseline on its own items with full per-cell power. *Cross-model* Bio comparisons rest on a systematically less hazardous, largely disjoint slice for Claude Opus 4; any direct model-vs-model Bio figure must restrict to the shared common pool or carry the caveat explicitly. Cells that cannot reach 50 scoreable pairs at all are excluded from inference (the basis for reporting a Claude Opus 5 cyber probe, ~75% filtered, only *as* a filtering result).

## 7. Reasoning-analysis coverage

For the cognitive overlay we score up to 100 matched transcripts per cell wherever plaintext chain-of-thought is available (272 cells; median 100/cell, 193 cells at exactly 100). Coverage is bounded by the same filtering asymmetry (Claude Opus 4/Bio judged cells are smaller) and by reasoning visibility: **GPT-5.6 Sol is excluded from the overlay** — it returns ~99% provider-encrypted reasoning, leaving the judge nothing to read — and the **sequential arm has no cognitive overlay**. Such cells are scored behaviorally only.
